# VercelSandbox

The `VercelSandbox` provider enables isolated cloud code execution using the [Vercel Sandbox SDK](https://sdk.vercel.com). It provides secure, ephemeral Linux environments that support mounting cloud filesystems via file synchronization.

:::info

For interface details, see [WorkspaceSandbox interface](/reference/workspace/sandbox).

:::

## Installation

```bash
npm install @mastra/vercel
```

## Usage

Add a `VercelSandbox` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent';
import { Workspace } from '@mastra/core/workspace';
import { VercelSandbox } from '@mastra/vercel';

const workspace = new Workspace({
  sandbox: new VercelSandbox({
    token: process.env.VERCEL_TOKEN, // Optional for OIDC on Vercel platform
    timeout: 60_000, // 60 second timeout (default: 5 minutes)
  }),
});

const agent = new Agent({
  name: 'my-agent',
  model: 'anthropic/claude-opus-4-5',
  workspace,
});
```

## Methods

### `start()`

Initialize and start the sandbox. If an ID is provided in the constructor, it attempts to reconnect to an existing sandbox.

```typescript
await sandbox.start();
```

Called automatically on first command execution or by `workspace.init()`.

### `stop()`

Stop the sandbox and release resources.

```typescript
await sandbox.stop();
```

### `destroy()`

Clean up sandbox resources completely. For the Vercel provider, this is equivalent to `stop()`.

```typescript
await sandbox.destroy();
```

### `executeCommand(command, args?, options?)`

Execute a shell command in the sandbox with streaming support.

```typescript
const result = await sandbox.executeCommand('ls', ['-la']);
const npmResult = await sandbox.executeCommand('npm', ['install', 'lodash'], {
  timeout: 60000,
  cwd: '/vercel/sandbox',
});
```

### `mount(filesystem, mountPath)`

Mount a filesystem into the sandbox. Vercel sandboxes use file synchronization to copy files from the source filesystem to the specified path.

```typescript
await sandbox.mount(s3Filesystem, '/data');
```

### `unmount(mountPath)`

Remove a mount from internal tracking. Note that Vercel sandboxes do not support true unmounting; files written during `mount()` remain in the sandbox.

```typescript
await sandbox.unmount('/data');
```

### `getInfo()`

Get sandbox status and metadata.

```typescript
const info = await sandbox.getInfo();
/*
{
  id: '...',
  provider: 'vercel',
  status: 'active',
  metadata: {
    timeout: 300000,
    createdAt: '...',
    instance: 'initialized'
  }
}
*/
```

## Vercel-Specific Methods

### `snapshot(options?)`

Create a snapshot of the current sandbox state for later restoration.

**⚠️ Important**: The sandbox is automatically stopped after creating a snapshot.

```typescript
const snapshot = await sandbox.snapshot({
  expiration: 3600, // Snapshot expires in 1 hour
});
```

### `getDomain(port)`

Retrieve the public HTTPS URL for a specific port running in the sandbox.

```typescript
const url = sandbox.getDomain(3000);
// Returns: https://<subdomain>.vercel.run
```

### `extendTimeout(duration)`

Increase the execution time limit for the current sandbox instance.

```typescript
await sandbox.extendTimeout(600_000); // Add 10 minutes
```

### `updateNetworkPolicy(policy)`

Modify network access rules for the sandbox to control which hosts or ports the environment can access.

```typescript
const updatedPolicy = await sandbox.updateNetworkPolicy({
  rules: [
    {
      action: 'allow',
      host: 'api.example.com',
      port: 443
    }
  ]
});
```

## Authentication

VercelSandbox supports two primary authentication modes: OIDC and explicit tokens.

### OIDC Authentication (Vercel Platform)

When running on the Vercel platform (e.g., in Vercel Functions), authentication is handled automatically via OIDC. No configuration is required.

```typescript
import { VercelSandbox } from '@mastra/vercel';

const sandbox = new VercelSandbox(); // Works automatically on Vercel
```

### Explicit Token Authentication

For local development, CI/CD, or running outside the Vercel platform, you must provide a Vercel API token.

```typescript
const sandbox = new VercelSandbox({
  token: process.env.VERCEL_TOKEN,
  teamId: process.env.VERCEL_TEAM_ID,
  projectId: process.env.VERCEL_PROJECT_ID,
});
```

## File Sync Mounting

Vercel sandboxes use a file synchronization approach (via `writeFiles()`) rather than FUSE-based mounting. When you mount a filesystem, Mastra walks the source tree and syncs the files to the sandbox environment.

```typescript
import { Workspace } from '@mastra/core/workspace';
import { S3Filesystem } from '@mastra/s3';
import { VercelSandbox } from '@mastra/vercel';

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
    }),
  },
  sandbox: new VercelSandbox(),
});

// Files from S3 are synced to /data in the sandbox on startup
```
